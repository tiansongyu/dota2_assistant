# 个人英雄池与统计口径

实现：`crates/hero-pool`。输入为当前账号的本地 `MatchRecord`，输出 `HeroStats` 和按用户配置筛选的候选英雄。英雄池配置按账号保存到 SQLite 的 `pool:ACCOUNT_ID` setting，离线可用。

## 统计

每个英雄按 `(account_id, match_id)` 去重，再按比赛开始时间倒序统计。未来时间和负数时间不纳入。当前实现包含：总场次、结果已知场次、胜败场次、原始胜率、先验平滑胜率、Wilson 95% 区间、最近 20/50 场、最近 90/180/365 天、指定版本、时间加权胜率、有效样本量、平均 KDA/GPM/XPM 和完整阵容覆盖率。

历史页面的聚合包含所有已导入模式。推荐器会另行筛选标准模式并重新统计，因此英雄池页面的全模式场次可能高于推荐原因中的场次。模式筛选规则见 [推荐模型](recommendation-model.md)。

结果缺失不计为失败，也不进入胜率分母。最近 20 场表示最近 20 条比赛记录，不是向前寻找 20 条结果完整的比赛；结果已知场次单独显示。KDA 计算为每场 `(kills + assists) / max(deaths, 1)` 后取均值，不等于“总击杀助攻除以总死亡”。缺失字段不参与该字段的均值。

`current_patch=None` 时当前版本窗口为空。导入的玩家比赛投影目前没有可靠 `patch` 字段，不能把空值当作当前版本。界面尚未实现完整的逐版本统计比较。

## 样本量与时间

原始胜率保留其历史含义；1 胜 0 负仍可显示历史 100%，但必须与 1 场样本及宽区间一起解释。评分使用以 0.5 为均值、强度为 10 的 Beta 先验：`(wins + 5) / (known_results + 10)`。这是一组工程初始参数，没有经过用户历史回测优化。

时间权重为 `2^(-age_days / half_life_days)`，默认半衰期 180 天。有效样本使用 Kish 公式 `(sum(w))² / sum(w²)`。它只反映权重集中程度；很旧且同龄的 100 场仍可能有 100 个 Kish 有效样本，所以推荐器另用时间权重之和限制近期熟练度和证据等级。

Wilson 区间针对未加权二项结果，未处理版本漂移或同一玩家比赛间的相关性；它不是本局胜率区间。当前没有训练个人概率模型。

## 候选规则

| 模式 | 可用英雄 |
| --- | --- |
| 自动 | 自动建议集 |
| 手动 | 用户明确加入的集合 |
| 混合 | 自动建议集与用户加入集合的并集 |

三种模式都先应用明确排除名单，再检查当前计划位置。没有手动位置配置的英雄不会进入该位置推荐。`lane_role`、Carry/Support 标签均不被强行转换为一至五号位。

自动建议的初始门槛为总使用至少 5 场，或近 90 天使用至少 3 场；排序考虑总场次的对数、近期场次的对数和平滑胜率，最多保留 20 位英雄。这是可解释的初始规则，不代表达到门槛就已经熟练，也未经过优化验证。

用户优先级范围为 `[-1, 1]`，对应推荐评分最多 ±5 分。它只改变合格候选的顺序，不能绕过明确排除、位置、已选或禁用规则。非零整数英雄 ID 与位置 1–5 在配置入口校验；游戏目录合法性由桌面命令层校验。

## 当前边界

- 自动池仍需要用户配置允许位置；当前没有可靠的五位置数据源。
- 分路、KDA、经济数据仅展示已知字段；没有用缺省值编造“常用位置”。
- 手动加入且没有历史的英雄可以进入候选，但其胜率使用先验、熟练度按零、可信度标为有限。
- 自动规则、半衰期和先验强度尚无足量真实数据的效果评估。
- 一至五号位的独立表现、跨版本稳定性指标、逐英雄完整克制/协同矩阵页面尚未完成；已有原始比赛和阵容可作为后续计算依据。

测试覆盖去重、未知结果、未来记录、字段空值、KDA 数值安全、非法 ID、排除名单与未知位置的硬约束。自动化测试证明这些规则按定义执行，不证明它们能提高玩家胜率。
