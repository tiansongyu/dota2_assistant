# 数据隐私

DPDA 不提供云账号、不上传截图、不收集遥测。历史和设置保存在本机，公开历史查询使用用户选择的 Account ID。首次账号设置会读取当前系统用户 Steam 安装目录中的 `config/loginusers.vdf`，只提取候选 Steam ID、昵称、最近使用标记和时间用于本机选择；也可手动输入 ID。检测本身不联网，不代表 Steam 登录，也不验证账号所有权。

## 网络访问

桌面历史同步访问 OpenDota 的公开 API，提供查询账号和分页参数；同步完成后自动补充最多 120 场已知比赛的详情，用于位置推断。总览的“补充位置数据”每次最多请求 240 场。只保留同队五人的槽位、英雄、分路和最小资源指标，不保存其他玩家的账号、昵称或聊天。普通启动仅读本地缓存。

默认游戏图标恢复脚本从本仓库的 GitHub Release 及 GitHub 资源域名下载固定 ZIP；缓存有效时不联网。维护者显式运行的原始图标下载器从固定版本的 dotaconstants 获取目录，并从 Valve CDN 下载英雄、技能、物品等图像；模板脚本也访问 Valve CDN。下载不提供玩家账号、不消耗战绩 API 请求；构建后图片和清单从程序本地加载，不在浏览时请求 CDN。下载器不上传个人缓存。Linux CLI 在显式运行 API 探测、历史同步或 `roles --refresh` 时访问对应服务；可选凭证从环境变量读取，不写报告或数据库。第三方平台会按其服务政策处理网络请求。

当前对局不查询对手 Steam ID 或个人历史，不读取游戏内存、注入进程或截获游戏网络。WGC 只捕获选定 DOTA2 窗口，裁剪区域留在本机。可视化校准载入的图片也只在本地处理。

检测结果中的昵称和最近使用信息仅用于界面展示；保存账号仍只持久化 Steam32 / Steam64。Steam 登录名、原始 VDF 与未知字段不写入数据库或日志；不读取密码、令牌存储或 Steam 其它配置文件。检测流程见 [自动账号发现](steam-account-discovery.md)。

## 保存与删除

- Windows：通常位于 `%APPDATA%\io.dpda.desktop\`，以 Tauri 实际解析的应用数据目录为准。
- Linux 调试 GUI：通常为 `$XDG_DATA_HOME/io.dpda.desktop/`，未设置时使用 `~/.local/share/io.dpda.desktop/`。
- 隔离启动脚本：新会话通常位于 `~/.local/share/dpda-debug-sessions/`，包含数据库副本和独立的 data/config/cache/state 目录；`--resume` 保留同一副本。
- CLI：`--db` 指定的路径。API 诊断 JSON 保存位置由调用者的输出重定向决定。

主数据库文件为 `dpda.sqlite`，日志在 `logs`。关闭应用后，可备份整个目录；SQLite 运行中可能存在 WAL/SHM 文件，不要只复制主文件作为一致性备份。删除本地数据前先退出程序，再删除相应文件；恢复依赖自己的备份或重新同步公开数据。

截图、诊断和日志可能包含账号、窗口标题、文件路径或游戏界面信息。提交公开 issue 前应检查并移除不必要内容。仓库测试 fixture 使用公开研究账号，保留最小字段与采集说明；这些数据不作为用户默认账号。
