# 推荐评分与历史回测

实现：`crates/recommender` 和 `crates/statistics`。当前模型输出个人英雄池内的排序分数与解释，未输出本局预测胜率，也没有训练或校准概率模型。

## 数据入口与硬约束

推荐器从当前账号比赛重新统计，不信任调用方传入的全模式展示聚合。默认只使用 `game_mode` 为 1、2、3、4、22 的历史记录；这些 ID 在固定的 dotaconstants 10.8.0 中分别对应 All Pick、Captains Mode、Random Draft、Single Draft、All Draft。Turbo（23）、特殊模式和未知模式不参与推荐。当前未保存可靠 `lobby_type`，因此这个筛选不能被称为“仅天梯数据”。

比赛必须在计算时刻之前结束。duration 缺失时，只有 `fetched_at` 早于该时刻才作为已可访问事实使用。比赛按账号和 match_id 去重，多个账号混入同一次个人推荐时返回空结果，避免混合个人统计。

候选必须在当前英雄池内、支持当前考虑的位置，且未被明确排除、已选或禁用。桌面新配置默认 `selected_role=0`：对有证据支持的一至五号位候选求并集，按英雄 ID 去重并统一排序。选择 1—5 时只考虑该位置。核心推荐函数仍逐次接收一个具体位置，自动模式由桌面组合结果；同一英雄不会因支持多个位置而重复出现或获得额外加分。

位置来自 `team-farm-lane-v1` 的个人详情证据，或用户明确覆盖。每位置至少需要 3 场符合规则的独立比赛证据才能成为自动建议；四/五号位无法区分时保留并列。`pool.roles` 没有英雄键时采用推断，非空数组覆盖推断，空数组 `[]` 表示明确不允许任何位置。缺少证据时不通过静态英雄标签填补位置，补充详情仍可继续改善覆盖。算法、来源与计数见 [自动位置分析](hero-pool.md#自动位置分析)。

返回数量最多为配置的 Top 3–5；候选不足时如实返回较少数量。不确定识别槽位由 Draft State 拦截，推荐器只接收已确认英雄，并在解释中标明阵容未定。位置推断和屏幕识别是两套独立证据，不能互相替代。

## 当前特征

个人熟练度统一到 `[0,1]`：

```text
personal = 0.60 × 时间加权平滑胜率
         + 0.30 × 长期平滑胜率
         + 0.10 × min(Kish有效样本, 时间权重之和, 50) / 50
```

没有个人结果样本时，胜率使用 0.5 先验、熟练度按零，得到 personal=0.45。时间加权胜率和长期胜率均使用均值 0.5、强度 10 的先验；这些权重没有经过实际效果调优。

克制分项统计“面对当前至少一个敌方英雄”的历史比赛，协同分项统计“与当前至少一个己方英雄同队”的历史比赛。只使用阵容完整且胜负已知的记录，同一场即使命中多个目标也只计算一次。各分项先对结果应用时间衰减，再向候选英雄自身的长期平滑胜率回退，先验强度为 20：

```text
condition_rate = (weighted_wins + personal_baseline × 20) / (sum(weights) + 20)
lineup_feature = clamp(0.5 + condition_rate - personal_baseline, 0, 1)
```

缺少对阵或协同样本时，该分项使用中性先验 0.5，并降低结论确定性。解释显示去重比赛数、胜场和时间权重之和。这里测量的是历史关联，不能证明英雄之间存在因果克制；也不是完整阵容的胜率。

指定 `current_patch` 时，对阵和协同仅使用已知且匹配该版本的记录。未指定时，跨版本历史按时间衰减使用，并明确提示版本未确认。长期熟练度仍保留跨版本历史。

## 评分、可信度与缺失特征

初始权重为个人 0.40、克制 0.30、协同 0.20、版本 0.10。当前没有经过核验、匹配位置/分段/版本的总体统计，所以版本项对所有英雄统一关闭，其余权重统一归一化。默认计算为：

```text
score = clamp(100 × (0.40 × personal + 0.30 × counter + 0.20 × synergy) / 0.90
              + 用户优先级 × 5, 0, 100)
```

各英雄使用相同分母，避免仅因某个英雄缺少对阵数据就把其个人项放大为全部评分。分数保留一位小数；它没有概率解释。仅给版本项正权重、其他项全为零的配置当前无可计算特征，因此被判为无效配置。

可信度目前是工程提示，不是经验证的统计置信等级：仅当个人已知结果至少 100 场、对阵和协同的 Kish 样本及时间权重之和均至少 20、阵容无未定槽位时显示“中等”，其他情况为“有限”。当前不显示“高可信”。

位置分析的 `strength` 与上述推荐可信度分别报告，均未经准确率或概率校准。当前位置证据只用于候选筛选；个人胜率、对抗和协同仍按候选英雄的可用历史计算，没有进一步限制为该位置的比赛。因此自动模式不能用同一英雄的分数比较“打中单比打辅助强多少”，也不能把支持位置的样本占比解释为当前局应选该位置的概率。

`PopulationEvidence` 只是未来外部统计的协议结构，现有程序没有获取、导入或评分该数据。版本强度、分段校正和可靠总体克制回退尚未接入；不能把结构体存在当作功能完成。

## 回测协议

```bash
cargo run -p dpda-recommender --example backtest -- DATABASE ACCOUNT_ID [ROLE] [MIN_TRAINING] [POOL_JSON_PATH]
```

默认位置 2、最少训练场次 20。省略 JSON 路径时读取数据库 `pool:ACCOUNT_ID` 配置；没有配置时使用空位置的默认池，报告跳过无候选记录，不能自行伪造用户英雄池。

**回测尚未接入桌面的自动位置流程。** CLI 回测只接受具体位置 1—5，读取显式保存的英雄池及 `roles`，不会读取比赛详情并合并自动 `suggested_roles` 或 `effective_pool`。英雄池的自动/手动/混合模式仍可使用，但回测位置许可须在传入配置中明确存在；仅在桌面获得了自动位置候选，不能保证当前回测有可评估候选。这个限制不意味着日常桌面推荐必须手选位置。

按测试比赛开始时间推进，每次训练仅使用此前已结束的标准模式比赛。缺少 duration 的记录，除非其采集时间能证明已在测试时刻前可用，否则不进训练。不会把测试比赛或同时仍在进行的比赛结果加入训练。

数据源没有过去的 BP 选人时间线，因此回测使用空阵容，不能把赛后完整阵容伪装成当时已知信息。英雄池与位置配置固定使用本次传入的配置，没有重建用户过去的手动选择。比赛结束时刻只是历史可用时刻的近似；数据源当时的公开/解析延迟无法从今天的快照中还原。

后续若接入自动位置回测，必须在每个测试时点仅使用此前可获得的位置证据，并重新建立建议池；不能把今天由全部历史推断的角色直接带入过去，再宣称没有数据泄漏。

报告包含实际选用英雄的 Top-K 覆盖、相同候选限制下的常用英雄基线覆盖、逐场训练样本数与推荐样本数、按版本分组结果、训练样本分布，以及被推荐列表覆盖的实际英雄的历史结果。无合格候选或训练不足时单独计数；没有可评估行时覆盖率为 `null`，不是 0%。

这些指标只回答“当前规则是否覆盖了玩家后来实际选择的英雄”。它们不表明改选其他英雄会赢，也不能用被覆盖比赛的历史胜率宣称推荐策略提高胜率。标准模式无明确版本时归到未知版本组。

## 尚未完成的验证

已提供 Brier Score、Log Loss 和 reliability 分桶计算函数，并以确定值测试数学结果。它们没有被用来把推荐分数转换为概率。Logistic Regression、LightGBM、训练/验证/测试分段、参数调优、概率校准和可视化 reliability diagram 均未训练或完成。

目前已有接口、数据导入与规则测试，但没有足量个人历史的基线比较结论、当前版本稳定性结论或胜率提升结论。位置推断仍需人工标签评估，详情抽样也不代表全历史位置分布。真实选人顺序数据、位置标签和可靠总体统计是后续模型评估所需证据。
