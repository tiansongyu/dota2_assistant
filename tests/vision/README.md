# 视觉测试集与验收记录

本项目尚未收集真实 DOTA2 截图，不提供准确率结果。Rust 中生成的纹理只用于算法和配置读写单元测试，明确属于合成材料。

## 数据集格式

截图由用户从自己的可见游戏界面采集。保存在本地测试目录，避免把玩家名称等无关信息上传仓库。`image_path` 相对于数据集 JSON；每个帧须有十个唯一槽位的人工标签。下面是字段示例，`samples` 为空，因此不能作为评估输入。

```json
{
  "schema_version": 1,
  "provenance": "real",
  "source_description": "填写采集设备、窗口模式、分辨率、DPI、游戏 UI 版本与采集日期",
  "samples": []
}
```

每个 sample 包含：

```json
{
  "session_id": "实际采集会话编号",
  "image_path": "frames/001.png",
  "timestamp_ms": 1000,
  "dpi": 96,
  "draft_screen": true,
  "slots": [
    {"slot_id": 0, "hero_id": 13, "locked": false}
  ]
}
```

需要补全 0–9 十个槽位；`hero_id: null` 表示空槽或不可辨认，`locked: true` 时 hero_id 必须有效。同一会话帧必须连续排列、时间戳严格递增。不同会话会重置时间稳定状态。标注的“锁定”必须通过实际画面序列或人工操作记录核验，不能由算法输出反填标签。

## 指标解释

- accuracy：十个槽位的最终确认英雄与人工标签完全一致的比例。未锁定标签按无确认英雄计算，因此需要同时查看召回率。
- precision：正确确认的英雄数量 / 所有确认输出数量。确认错英雄计入错误。
- recall：正确确认的英雄数量 / 人工标注已锁定英雄数量。
- false_positive_rate：人工标注未锁定/空槽而算法输出确认英雄的数量 / 所有未锁定/空槽标签数量。
- latency：OpenCV 分析和像素缓存耗时，不包括图像文件解码、屏幕捕获和推荐计算。

无分母的比率输出 `null`。完整序列包括连续帧确认的预热期，不跳过不利帧。数据集输出保留 `real` 或 `synthetic`，不得改写为实机测试结果。
